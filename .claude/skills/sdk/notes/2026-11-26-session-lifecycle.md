Swift's `AgentSession` follows a conversation through one explicit lifecycle. What the other client SDKs need to check:

- **Closing reaches the router whatever the socket is doing.** Over the socket only while it is open and the router takes it; otherwise `POST /v1/agents/sessions/{id}/stop`: before start, while the token is fetched or the upgrade is under way, and once the socket dropped. A dropped watcher only detaches, and a voice call is held until somebody stops it, so a close sent into a dead socket leaves the agent on the call. Kotlin sends `Command.Close` into any socket it holds and swallows the failure, so a dropped one is never stopped. A close during a connect must also stop that connect from opening the socket afterwards, and close the socket before the HTTP stop: watching an ended text conversation carries it on.
- **A refused upgrade never reads as connected**, and starting again tries again. One that dropped once open is not reopened (no resume semantics).
- **Stopping watching without stopping the session** (Swift `detach()`, JS `stopWatching()`), used when a screen follows a conversation something else holds. Attaching to a session whose socket is refused throws and leaves the session running.
- **Skills still running survive the reply about them.** Track `delegated` by `task_id`, apart from the state: `responded`, `heard` and `interrupted` go back to working on what is left, not to idle, and settling one of two runs of a skill leaves the other. JavaScript's `state.ts` filters by skill name and derives the list from the state, so it loses both.
- **`tool_cancel` stops a device tool that is running**, and nothing is sent for it; an approval answered while the cancel arrives does not run it.
- **A 401 drops only the token it refused.** A late 401 for an older token keeps the one fetched since, and requests refused together fetch one new token. Dart does this for HTTP requests only, in `Backend` (`lib/src/core/backend.dart`, called from `wire.dart` as `expireBackendToken`). Chat and video refresh with `streamCredentials(refresh: true)`, which still drops whatever token is held, so a late chat or video refresh can throw away one an HTTP 401 fetched since; Swift's `Identity.refresh()` does the same.
