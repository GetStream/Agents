Connectors and router configs carry a `sync_hash`, as agent configs do: `createConnector` (`CustomConnectorRequest.sync_hash`) and `createRouterConfig`/`updateRouterConfig` (`RouterConfigRequest.sync_hash`) take the fingerprint of the file a sync sent, and `Connector.sync_hash` and `RouterConfig.sync_hash` return it. Any write without one clears it; a router config replace with the stored hash and the same content writes nothing, and a connector sent again with the same definition and another hash keeps its revision and records the hash. Every generated client is regenerated in this change; no SDK computes or sends the hash yet. Other SDKs need to update: once the CLI's hash for a connector or router file is settled (AI-3664), a server SDK that syncs those files sends it the same way.
