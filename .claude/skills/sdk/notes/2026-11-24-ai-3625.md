An app runs one import at a time on a router, and a router at most four (AI-3625): `importData` (`POST /v1/data/import`, server-side only) now answers 409 with two meanings, told apart by `code`. `import_running` is an import of the app already running on this router: the same import can succeed once it ends. `conflict` is still "already holds data here", which `full=true` writes over. A 503 `unavailable` is the router running as many imports as it takes at once: try again later. An import also ends, answered 504 `timeout`, when one line has taken a minute to arrive. Go, JavaScript and Python (`plugins/stream`) have the regenerated clients. Other SDKs need to update: a hand-written import wrapper should read the 409's `code` rather than take every 409 as "already holds data here", and treat the 503 as one to retry.
