A policy that sets `prompt_injection_fail_closed` holds a response the prompt injection screen could not check, and the socket's `error` frame for that turn now has the code `prompt_injection_unchecked` (AI-4177). The server refuses the reply the same way as a flagged one, so the kept conversation drops it, but the client conversations clear a refused reply's streamed text only when the code is `prompt_injection`. They must clear it on `prompt_injection_unchecked` too, or the unscreened text stays on screen. The places are `refused()` in `sdks/js/src/conversation.ts` (the `error` frame case), the `PROMPT_INJECTION` code check in `sdks/kotlin/core/src/main/kotlin/io/getstream/agents/android/core/Conversation.kt`, and the `"prompt_injection"` comparison in `sdks/swift/core/Sources/StreamAgents/Conversation.swift`. The generated clients are regenerated in the PR; only these hand-written conversations need the change.
