`AgentConfig`, `AgentConfigRequest` and `AgentConfigPatch` gain `identity`, an `AgentIdentity` `{agent_id, user_id, user_name}` (AI-3900): who the agent is in Stream Chat in a session that names nobody. A session naming the config uses each field set, from an end user's device or a backend, unless its request names its own `agent_id`, `user_id` or `user_name` (one at its default counts as naming none); a session carrying on a `conversation_id` keeps that conversation's agent id. Left out or null on an update (PUT), the stored identity stays; an empty object removes it; a patch replaces it whole. `agent_id` and `user_id` starting with `!` are refused (400). `syncAgent` does not take it and keeps the stored one. Server-side only, as every config write is. Every SDK has the field in its regenerated client (Go `acceleration.AgentIdentity`). Server SDKs (JavaScript, Python `plugins/stream`, .NET, Ruby, Rust, PHP) that wrap config create, update or patch should expose `identity` there. Swift, Kotlin and Dart need nothing, since agent configs are server-side only.
