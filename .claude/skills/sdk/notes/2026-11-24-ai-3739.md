`memory.app_id` and `memory.filter` on a session (`SessionMemory`) are documented as what they are when an end user's device sends them (AI-3739): a device may set them or leave them out, so they narrow recall but keep nothing from the user. Memories a user must not reach across groups, such as workspaces, need a user id per group, named by the backend (a device may only name its own user id). Nothing changed in what the router accepts. Go, JavaScript, Python, Swift, Kotlin, Rust, PHP and .NET have the regenerated clients (Dart's carries no field docs); the Volt dashboard's generated types (`src/gen/agents/endpoints/agents.d.ts`) still need them. Hand-written docs that promise more should say the same for both fields: Kotlin's `Options.Memory` (`filter`, and `appId` "Separates two of your apps") and the memory section of `sdks/kotlin/README.md` ("keeps two of your apps ... apart"), Swift's `StreamAgents.Memory` and Dart's `SessionMemory` in `models.dart`.
