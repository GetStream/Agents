A socket opened from a browser cannot send headers, so the router counted every browser socket as client `api` (AI-3335). The router now also reads `X-Stream-Client` from the query parameter of the same name, on the socket routes only (`/v1/agents/sessions/{id}/events`, `/v1/agents/socket`, `/v1/dispatch` and `/v1/{modality}/stream`), and only when the header is absent; Stream's chat clients send it there too. The value only picks the activity row, under the same rules as the header (`store.AuditSource`: a name starting `stream-agents-` is `sdk`, an unknown one is `api`). JavaScript adds `X-Stream-Client=stream-agents-js-v<VERSION>-browser` to the URL when it opens a socket with the browser's own WebSocket (`openSocket` in `sdks/js/src/backend.ts`); a socket passed in as the `webSocket` option is left as it is. Go has no browser socket and needs no change. Other SDKs need to check their sockets: Dart opens its session socket with `WebSocket.connect(uri)` and no headers (`sdks/dart/stream_agents/lib/src/core/socket.dart`), so it should add `X-Stream-Client=stream-agents-dart-v<sdkVersion>` to that URI. Kotlin and Swift need no change: Kotlin sends the header on the handshake (`AgentSessionTest` checks it), and Swift opens its session socket with `backend.headers()`, which carry `X-Stream-Client` (`sdks/swift/core/Sources/StreamAgents/AgentSession.swift`). An SDK adds the query parameter only where its socket cannot send the header.
