The handle `responses.create` returns reads only its own turn's items, and a turn with no id has none (AI-3571). The router answers a question with an empty `id` for a session that records nothing (incognito), for a speech-to-speech session, whose model decides what a turn is, and for the retry of a `request_id` already taken. A handle built on that empty id used to leave `response_id` out of `GET /responses/items`, which reads every turn in the session: the whole conversation passed off as this turn's, or nothing at all for an incognito session, with no word of why. Go now refuses before asking: `AgentResponse.Items` (built by `newTurnItems` in `sdks/go/client/responses.go`) fails with `ErrUnnamedTurn`, whose text every SDK copies: "the turn has no id, so it has no items of its own to read: the router names no turn for an incognito session, a speech-to-speech session or the retry of a request_id already taken; follow the answer on Session.Events, or read Session.Responses.Items for a session that records its turns" (with each SDK's own names for the session's events and its responses' items). `Responses.Items`, the whole session's, still reads every turn. A caller that read a turn handle's items for the whole session now gets the error, as the root `CHANGELOG.md` says under Breaking Changes. Other SDKs need to update: Python first, whose `AgentResponse.items` (`plugins/stream/vision_agents/plugins/stream/responses.py`) is what the QA ran into, then JS (`sdks/js/src/responses.ts`), Swift, Kotlin, Dart, .NET, Ruby, Rust and PHP: each turn handle refuses to read items when its id is empty, with that error, and the session-wide items keep reading every turn.
