The handle `responses.create` returns reads only its own turn's items, and a turn with no id has none (AI-3571). The router answers a question with an empty `id` when the session records nothing (incognito), and for the retry of a question already taken. A handle built on that empty id used to leave `response_id` out of `GET /responses/items`, which reads every turn in the session: the whole conversation passed off as this turn's, or nothing at all for an incognito session, with no word of why. Go now refuses before asking: `AgentResponse.Items` (built by `newTurnItems` in `sdks/go/client/responses.go`) fails with `ErrUnnamedTurn` when the turn has no id, saying the answer is on `Session.Events`. `Responses.Items`, the whole session's, still reads every turn. Other SDKs need to update: Python first, whose `AgentResponse.items` (`plugins/stream/vision_agents/plugins/stream/responses.py`) is what the QA ran into, then JS (`sdks/js/src/responses.ts`), Swift, Kotlin, Dart, .NET, Ruby, Rust and PHP: each turn handle refuses to read items when its id is empty, with an error naming incognito and pointing at the session's events, and the session-wide items keep reading every turn.
