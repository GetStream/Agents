An agent folder loads only the files inside it (AI-3732). Go (`sdks/go/agents/folder.go`), Python (`plugins/stream/.../folder.py`) and JavaScript (`sdks/js/src/folder.ts`) resolve the agent directory to an absolute real path once, then refuse any file read whose real path is outside it, with an error that says the path "links outside the agent directory". That covers `agent.yaml`, `instructions.md`, `guardrail.md`, every file under `skills/` (`*.md`, a folder's `SKILL.md` and its other files), `knowledge/` itself and every document under it, `knowledge/urls.yaml`, and every file under `simulations/`. A linked file that stays inside the directory is still read (Go does not follow a linked directory in a walk), and an agent directory reached through a link, or named relative to the working directory, still loads. The loaders differ in which outside links they would not read anyway they refuse or skip (Go skips a linked folder or a non-markdown link directly in `skills/` and takes a dangling `instructions.md`, `guardrail.md` or `urls.yaml` link as a missing file, where Python refuses these); neither reads anything outside. A link that leads to itself is an error in any file they read, except that Python skips one in `simulations/`. Knowledge now leaves out hidden files and folders (`.draft.md`, `.git/`) and `__pycache__`, as skill folders already did. Other SDKs need to update: a folder loader resolves the agent directory and each path it reads to an absolute real path, refuses one outside the directory, and skips hidden entries and `__pycache__` in knowledge.
