An agent folder loads only the files inside it (AI-3732). Go (`sdks/go/agents/folder.go`) and Python (`plugins/stream/.../folder.py`) resolve the agent directory to an absolute real path once, then refuse any file read whose real path is outside it, with an error that says the path "links outside the agent directory". That covers `agent.yaml`, `instructions.md`, `guardrail.md`, every file under `skills/` (`*.md`, a folder's `SKILL.md` and its other files), `knowledge/` itself and every document under it, `knowledge/urls.yaml`, and every file under `simulations/`. A linked file that stays inside the directory is still read (Go does not follow a linked directory in a walk), and an agent directory reached through a link, or named relative to the working directory, still loads. The loaders differ in which outside links they would not read anyway they refuse or skip (Go skips a linked folder or a non-markdown link directly in `skills/` and takes a dangling `instructions.md`, `guardrail.md` or `urls.yaml` link as a missing file, where Python refuses these); neither reads anything outside. A link that leads to itself is an error in any file they read, except that Python skips one in `simulations/`. Knowledge now leaves out hidden files and folders (`.draft.md`, `.git/`) and `__pycache__`, as skill folders already did. JS, .NET, PHP, Ruby and Rust followed (AI-3760), each through one helper every read goes through (`insideAgent`, `Inside`, `inside`), and now have both halves; JS already left hidden entries and `node_modules` out of knowledge. They also refuse `skills/`, `knowledge/` and `simulations/` themselves, and a link that loops, wherever they read. Where they differ: JS does not follow a linked folder in a walk (as Go) and now reads a linked skill or simulation file that stays inside; .NET, PHP, Ruby and Rust check every entry of `skills/`, so an outside link there is refused even when it is not a skill (as Python), and follow a linked folder inside a skill folder, as .NET and Rust also do in knowledge, refusing it when it leads out; PHP refuses a dangling link wherever it reads one, and clears its realpath cache on each load, since a long-lived process would otherwise still see a file that has since become a link. Swift, Kotlin and Dart load no agent directory, so nothing is left to update.
