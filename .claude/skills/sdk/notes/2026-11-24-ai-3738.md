`say` on the session events socket (`GET /v1/agents/sessions/{id}/events`) is now server-side only, as `POST /v1/agents/sessions/{id}/say` already was (AI-3738). From an end user's device the router answers it with an `error` frame (`context` `command`) and says nothing; the socket stays open. Go and Python only send it from a backend and need nothing. JavaScript has the regenerated spec; its `session.say()` still works from Node with a server token, and its doc should say it is server-side only. Kotlin (`AgentSession.say`, `Command.Say`), Swift (`AgentSession.say`, `Command.say`) and Dart (`AgentSession.say`, `SayCommand`) run only on a device, where it can never succeed: remove them. Until then, their `say(..., interrupt: true)` stops what the agent is saying and then says nothing.
