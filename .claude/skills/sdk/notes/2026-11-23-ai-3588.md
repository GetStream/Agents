A `return_url` an end user's device sends (`CreateSessionRequest`, on `createSession` and the session socket's `start` frame) is kept only when its origin, or its native app scheme, is listed in the app's policy: `Policy.device_return_urls` (`PUT /v1/policies/app`, server-side only), entries such as `https://app.example` or `com.example.app` (no colon). Any other is dropped and the session opened as if none was sent, so its consents go back to the dashboard; a server-side caller needs no entry, and an organization's policy that sets them is refused with 400 (AI-3588). The generated models are regenerated in every SDK; no hand-written SDK code changes. Other SDKs need to update: an SDK that wraps the app policy (`Policy`) as a type of its own adds `device_return_urls`, and the mobile SDKs' docs (Swift `returnURL`, Kotlin and Dart `returnUrl`) say the backend lists the app's scheme there first.
