A device's PATCH of a scheduled task may move `next`, or give a `schedule` whose first run is earlier than a pending run, only to or past that run (AI-3921); a move earlier, or a `next` with no run pending, is answered 400 `interval_too_short`. A backend key keeps the 15 minute floor. The generated models are regenerated here. The hand-written doc comments of `update` in the JS SDK (`sdks/js/src/scheduled-tasks.ts`), the Dart SDK (`sdks/dart/stream_agents/lib/src/core/scheduled_tasks.dart`) and the Kotlin SDK (`sdks/kotlin/core/src/main/kotlin/io/getstream/agents/android/core/ScheduledTasks.kt`) still say a move lands 15 minutes from now at the soonest unless it is no earlier than the current next occurrence; add that an end user's device may move a next occurrence only to or past the one still to come. No SDK code change is needed.
