A `speak` frame's `voice` on a text-to-speech socket (`/v1/tts/stream`) must be the session's voice (AI-3836): the one the `start` frame asked for or the one the router reported. Any other voice is refused with an `invalid_request` error saying to open a new session, and nothing is spoken. Ruby's `speak(voice:)` (`sdks/ruby/lib/getstream/vision_agents/router.rb`) passes `voice` through, so its doc comment should say it takes only the session's own voice; to speak in another voice, open a new session. Other SDKs with a text-to-speech `speak` helper should document the same rule. No SDK code change is needed.
