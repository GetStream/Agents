Updating, pausing or resuming a scheduled task (`updateScheduledTask`, `pauseScheduledTask`, `resumeScheduledTask`) can now answer 409 with the code `task_changed` when the task changed between the router's read and its save: another edit or pause, or a worker claiming, holding or finishing an occurrence (AI-3496). Nothing of the request was saved, so reading the task again and retrying is the answer. The other 409s on these methods (`conflict` for a completed task, `too_many_tasks` at the active limit, which a resume now also answers under the same lock as a create) are final. Go's generated client has the new `JSON409` fields, and the Python plugin and JavaScript types are regenerated. Kotlin's `ScheduledTasks.update`, `pause` and `resume` document the retry: `AgentsException.Http.code` is `task_changed`, read the task again with `get`, and any other 409 is final. Other SDKs need to update: .NET, Ruby, Rust, PHP, Swift and Dart tell `task_changed` apart from the final 409s and document the retry on those three methods.
