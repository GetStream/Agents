A router of several shards reads agent logs and a connection's tool calls in one shard, the one that ran them. `listAgentLogs`, `streamAgentLogs`, `getAgentLog` and `listConnectionInvocations` gained an optional `region` query parameter that reads that shard instead (a 400 when it names no shard, a 503 `shard_unavailable` when none of its routers answers), and answer `X-Shard`, the shard that answered, absent on a deployment of one shard. The logs filtered to a `session_id` are read in the session's shard without `region`. Go has the parameter as `Region` on the generated params (`GetAgentLogWithResponse` now takes a `*GetAgentLogParams`) and no method reads logs or invocations yet. Other SDKs need to update: regenerate the params for `region`, and wherever an SDK lists logs or invocations, read `X-Shard` and send it back as `region` to page or open a row of that shard.
