`RouterConfigRequest` (`createRouterConfig`, `updateRouterConfig`) and `CustomConnectorRequest` (`createConnector`) take `check_changes`, as `SyncAgentRequest` does. With it, a router config replace or a connector create is refused with a 409 `unsynced_changes`, the code agent sync uses, when the stored config or the newest revision carries no `sync_hash` (no sync wrote it, or a write that is no sync cleared it) and says something else than the request. The same content is not refused, and a create with nothing stored is not refused. Left out, the write goes ahead as before. Every generated client is regenerated in this change; no SDK sends it yet. Other SDKs need to update: a server SDK that syncs router config or connector files and asks before writing over an edit sends `check_changes` and handles `unsynced_changes` as it does for an agent sync.
