A router of several shards no longer reads one shard from another. `listCalls` and `getCall` dropped the `X-Unreachable-Shards` header (it was never released, and replaces the AI-3695 note): the call and session lists read a shared index every shard ships to a few seconds behind, and a call's own routes (`/v1/agents/calls/{id}...`) are answered by a node of the shard it lives in, a 503 `shard_unavailable` when none answers. `Session` and `Call` gained `region`, the shard a listed one is kept in. Go has it as `acceleration.Session.Region` and `acceleration.Call.Region`, and no longer checks the header in `Sessions.newestCall`. Other SDKs need to update: regenerate the models for `region`, and drop any reading of `X-Unreachable-Shards`.
