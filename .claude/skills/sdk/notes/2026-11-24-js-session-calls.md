JavaScript reads a session's timeline and decisions from its newest call, settling its part of the «Calls have an id of their own and a `session_id`» note in `../SKILL.md`. `sessions.timeline(id)` and `sessions.decisions(id)` (`sdks/js/src/sessions.ts`) list the session's calls with `session_id` and `limit=1`, read the newest one's `getCallTimeline` or `getCallEvents`, and reject with the exported `NoCallError` (its `sessionId` the session's) when the session has none, as Go's `client.ErrNoCall`. They used to pass the session id as a call id, which the router answers 404 `call_not_found` for every call started since. JavaScript sends no other session id to `/v1/agents/calls/{id}`: `sessions.tokens` reads `/v1/agents/sessions/{id}/tokens`. Python (`plugins/stream`), .NET, Ruby, Rust and PHP still owe theirs.
