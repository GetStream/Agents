`AgentConfigPatch` has a new optional field, `updated_at` (a date-time): the `updated_at` of the config a patch was made from (AI-3516). Sent, `PATCH /v1/agents/configs/{id}` refuses the patch with a 409 `conflict` when the config was saved after it; left out, nothing changes for the caller, and the router now makes the patch on the row as it stands, so two patches at once to different fields both land. Go has it through the regenerated `acceleration.AgentConfigPatch.UpdatedAt` (`sdks/go/acceleration/generated.go`), Python through the regenerated `AgentConfigPatch.updated_at` and JavaScript through the regenerated `Schemas["AgentConfigPatch"]`. Other SDKs need to update: .NET, Ruby, Rust and PHP add the field to their `AgentConfigPatch` model when they regenerate, serialised as RFC 3339 and left out when unset. Swift, Kotlin and Dart have no patch operation, which is server-side only. No SDK sends it on its own: a helper that patches a config (`UpdateConfig` in Go, `updateConfig` in JavaScript) passes it through only when its caller set it.
